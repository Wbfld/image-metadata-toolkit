## Explicit semantic differences

| ID | Toolkit | Incumbent consequence |
| --- | --- | --- |
| date-timezone | Keeps normalized and lexical dates; preserves only an actual EXIF offset and never infers a runtime timezone. | exifr may convert dates to Date/UTC; ExifReader retains EXIF lexical values. |
| rationals | Keeps normalized numeric values plus exact numerator/denominator source values. | exifr commonly returns decimals; ExifReader exposes numeric pairs. |
| duplicates-ordering | Retains source-ordered fields, RDF properties, IPTC candidates, blocks, and conflicts. | Flat object projections cannot represent duplicate candidates or source ordering without an explicit loss policy. |
| raw-semantic | Separates raw, lexical, normalized, and semantic values with provenance. | Flat values are convenience projections rather than round-trip models. |
| warnings-errors | Uses coverage, completeness, typed statuses, diagnostics, and stable reason codes. | Missing, undefined, null, callback, and thrown-error semantics are library-specific and are not treated as success. |
| metadata-families | Preserves distinct EXIF, URI/local-name XMP, IPTC semantic, and ICC families. | Unsupported or differently-shaped families remain explicitly non-equivalent. |
| writing | Uses exact operations, atomic output, reparse, and encoded-payload evidence. | No broad EXIF-object writer compatibility claim is made. |

## Unsupported mappings

- implicit path, URL, and DOM image loading
- callback metadata attachment
- object-URL thumbnail creation
- wholesale EXIF dictionary rewrite
- lossless flattening of duplicate, RDF/XMP, IPTC, or ICC data
