# B02 HEIF/AVIF item semantics

B02 adds a bounded structural item graph for HEIF and AVIF. It does not decode
pixels, interpret image-sequence tracks, rewrite HEIF/AVIF, fetch external data,
or make a claim that a structurally parsed file is displayable.

## Public model

`MetadataResult.heif` contains one `HeifItemGraph` per discovered `meta` box.
Each graph retains:

- primary item identity from `pitm`;
- `iinf` item IDs, item types, UTF-8 names, MIME content types and encodings,
  and hidden flags;
- `iloc` construction method, data-reference index, base offset, every extent
  index/offset/length, absolute source offset where meaningful, and resolved
  byte length;
- `dref` type, self-contained flag, resolvability, source range, and no remote
  payload;
- `ipco` properties and `ipma` associations, including essential bits,
  dimensions, auxiliary type/subtypes, and source ranges;
- ordered `iref` relationships for `thmb`, `auxl`, `dimg`, `cdsc`, `iloc`, and
  unknown reference types;
- structural `grid`, `iovl`, and `iden` derived descriptors, including grid
  dimensions/order and overlay offsets.

Construction methods are represented as `file`, `idat`, `item-offset`, or
`unsupported`:

- method 0 reads file-relative extents;
- method 1 reads extents relative to the containing `idat` payload;
- method 2 follows ordered `iloc` item references and applies each extent as a
  bounded subrange of the referenced item.

All arithmetic is safe-integer checked. Multiple extents are retained and
assembled only when each extent is valid. Empty extents are represented as
empty; a zero-length extent in a multi-extent item is rejected because it
would make the source boundary ambiguous. Method 0 data references resolve
only the validated self-contained `url ` / `urn ` form. External or unknown
references are inventoried and marked non-resolvable; the parser and range
planner never perform network I/O.

`complete` is true only when the graph has no malformed, unsafe, truncated, or
limit diagnostic. A graph can still be returned with partial structural facts
when one item is unsupported or unsafe. Such facts retain their warning code
and resolution state rather than being guessed.

## Bounded range reads

Metadata-scoped `Blob`/`File` input uses `src/heif-range.ts`. It scans bounded
box headers, reads the `meta` structure, and resolves only selected Exif and
RDF/XML XMP item payloads. It uses the same method 0/1/2, self-contained data
reference, multi-extent, cycle, and cumulative-byte checks as the in-memory
parser. When the metadata layout cannot be reconstructed safely, it returns
`null` to the existing input layer, which performs a bounded full-read fallback
so malformed data remains diagnosable. A range read is never reported as
complete when only a partial scope was inspected.

## Evidence

`tests/heif-b02.test.ts` uses deterministic structural fixtures and covers:

- HEIF and AVIF graphs;
- method 0 file extents with multiple discontiguous extents;
- method 1 `idat` extents;
- method 2 item-offset references and cycle rejection;
- self-contained and external data references;
- ordered thumbnail, auxiliary, description, derived, overlay-input, and
  item-offset relationships;
- `ispe`, `auxC`, grid, and overlay facts;
- malformed derived descriptors, excessive box limits, and unsafe references;
- metadata-only `Blob` range materialization without reading a large trailing
  box payload.

The retained execution artifact is generated by:

```sh
npm run test:heif
```

It writes `reports/heif-b02-evidence.json` and
`reports/heif-b02-evidence.md`. The reports contain fixture paths, byte
lengths, SHA-256 values, package version, source-manifest identity, limits,
case assertions, and warning codes. They contain no third-party image bytes.

HEIF/AVIF image writing and image sequences remain outside B02 and are not
implied by this inspection model.
