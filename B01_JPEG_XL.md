# B01 — JPEG XL dimensions and compressed metadata

Status: **implemented with executable evidence**

## Scope and policy

The JPEG XL reader now reports dimensions from the codestream size header in
both naked codestreams and ISO-BMFF containers. It reads a complete `jxlc`
codestream or the ordered header of `jxlp` fragments without decoding pixels.
Raw codestreams remain a separate result: their dimensions may be reported,
but no container metadata block is invented and their non-addressable metadata
is reported as an explicit unsupported structure.

`Exif` and `xml ` boxes are decoded directly. A `brob` box is decoded only
when its four-byte underlying type is `Exif` or `xml `; its compressed payload
is passed through the bounded `ParseOptions.jxlBrotliDecompressor` hook or the
runtime's `DecompressionStream("brotli")`. The hook receives a copy of the
compressed bytes, a maximum output budget, and the caller's abort signal.
Returned output is copied and rejected when it exceeds the configured
decompressed metadata budget. No Brotli dependency is included in the core
package.

The parser never treats a failed or unavailable Brotli decoder as decoded
metadata. Unsupported platform support is `UNSUPPORTED_COMPRESSION`; malformed
compressed data and over-budget output remain visible diagnostics. Aggregate
metadata bytes, decompressed bytes, UTF-8 string bytes, packet counts, box
counts, input bytes, and warning counts all use the repository's resolved
security limits. Compressed
metadata fields retain the logical block identity, while source offsets inside
the decompressed byte stream are null because they have no physical source
range. Uncompressed fields retain file-relative packet and TIFF provenance.

## Standards and provenance

The pinned source record is [data/jxl/sources.json](data/jxl/sources.json).
It records the retrieval date, edition, authority, license, and why no source
hash is present for remotely consulted copyrighted standards. The normative
bases are ISO/IEC 18181-1:2024 and ISO/IEC 18181-2:2024. The pinned BSD-3-Clause
libjxl reference text is an implementation cross-check only; its code and
metadata tables are not used by the reader.

## Acceptance evidence

| Requirement | Implementation | Executable evidence |
| --- | --- | --- |
| Raw and container dimensions | `src/parsers/jxl.ts` codestream size-header reader | `tests/jxl-b01.test.ts` — raw, small, `jxlc`, and split `jxlp` dimensions |
| Brotli-compressed Exif/XML | `brob` dispatch and bounded decoder hook/platform stream | `tests/jxl-b01.test.ts` — actual Node Brotli compression/decompression and async hook |
| Chrome/platform limitation | `UNSUPPORTED_COMPRESSION` from unsupported stream format | `tests/browser/jxl-b01.spec.ts` — Chromium and Firefox public API run |
| Raw/container separation | raw path does not create XMP/Exif blocks | `tests/jxl-b01.test.ts` — codestream bytes followed by XML remain metadata-free |
| Safe arithmetic and malformed structures | checked box sizes, extended sizes, fragment sequences, output budgets, aggregate metadata/string/packet limits, and warning caps | `tests/jxl-b01.test.ts` — truncation, contradiction, invalid output, limits, and malformed `brob`; retained evidence includes the aggregate limit case |
| Provenance and selection | physical container blocks plus logical compressed-field provenance; selected families skip decompression | `tests/jxl-b01.test.ts` — Exif source linkage and no-call selection case |

The redistribution-safe JSON and Markdown evidence are generated by
`npm run test:jxl` from compact synthetic byte fixtures. They contain no image
or third-party payloads:

- `reports/jxl-b01-evidence.json`
- `reports/jxl-b01-evidence.md`

The Node evidence uses only the Node built-in Brotli implementation in the
test/evidence process. Browser evidence uses the repository's existing pinned
Playwright implementations and is run with:

```sh
npx playwright test tests/browser/jxl-b01.spec.ts --project=chromium --project=firefox
```
