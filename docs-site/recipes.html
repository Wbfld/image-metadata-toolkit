Runtime recipes

Every recipe keeps the dependency-free core local. Node-only filesystem access belongs to the Node entry point; the fetch adapter is explicit.

Browser

import { parseMetadata } from "browser-image-metadata";\nconst result = await parseMetadata(file);

Worker

import { createMetadataWorkerClient } from "browser-image-metadata/worker";\nconst client = createMetadataWorkerClient(new Worker("./worker.js", { type: "module" }));

Node

import { parseMetadata } from "browser-image-metadata/node";\nconst result = await parseMetadata("image.jpg");

Deno

import { parseMetadata } from "npm:browser-image-metadata@2.0.0-alpha.3";\nconst result = await parseMetadata(await Deno.readFile("image.jpg"));

Conditional; execute npm run test:deno when Deno is installed.

Bun

import { parseMetadata } from "browser-image-metadata";\nconst result = await parseMetadata(await Bun.file("image.jpg").arrayBuffer());

Not advertised until a Bun CI run is retained.

Vite

import { parseMetadata } from "browser-image-metadata";\nexport async function inspect(file) { return parseMetadata(file); }

Next.js and React

"use client";\nimport { parseMetadata } from "browser-image-metadata";\n// Call parseMetadata from a file input change handler.

Serverless

import { parseMetadata } from "browser-image-metadata/node";\nexport async function handler(request) {\n  return new Response(JSON.stringify(await parseMetadata(await request.arrayBuffer())));\n}

Provider limits, request authentication, and storage are application policy.

Evidence and boundaries

Chromium, Firefox, Node, worker, package, and example recipes are executed in this repository. Deno and Bun remain conditional/unverified when their runtimes are unavailable. No recipe implies browser support for Node-only filesystem APIs.
