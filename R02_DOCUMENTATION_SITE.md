# R02 documentation site and local-only playground

The documentation site is a deterministic static artifact generated by
`scripts/generate-docs-site.mjs`. It is intentionally framework-free so the
documentation toolchain cannot add dependencies or runtime code to the core
package. Run `npm run docs:generate` to rebuild it after source registries or
capability data change, and `npm run docs:check` to fail on stale generated
data, missing local links, duplicate identities, missing CSP, or unsafe
playground sinks.

## Generated coverage

The generated registry has separate searchable pages for:

- EXIF tags from `data/metadata-registry.json`;
- IPTC datasets and structured resources from the pinned 2025.1 technical
  reference, with the 2023.1 source hash retained for edition provenance;
- XMP properties identified by namespace URI and local name, with prefixes
  displayed only as aliases;
- decoded ICC semantic fields exposed by the package;
- all seven T02 policies;
- W07 field, namespace/property, family, sensitivity, block,
  associated-image, and structured-resource selectors;
- format and capability manifest entries.

Every generated entry retains a stable identity, source reference, type or
format, cardinality where known, version, validation and/or controlled values,
sensitivity or raw behavior where the source defines it, and the registry,
IPTC, and capability SHA-256 values. Generated anchors are derived from the
stable identity and are deterministic.

## Playground and transport boundary

`docs-site/playground.html` accepts a local `File` and reads it with
`arrayBuffer()`. It calls the built public parser, T01 privacy auditor, W01/W07
mutation API, safe JSON adapter, and W08 preservation verifier. It displays
bounded fields, coverage/provenance, privacy categories and reason codes,
planned edit state, byte-change evidence, and verification state. Values are
rendered with `textContent`; privacy output uses the safe default serializer
and does not display sensitive raw values.

The normal pages set `connect-src 'none'`, prohibit objects, frames, form
submission, remote scripts, remote styles, and remote fonts, and use only
same-origin static assets. The fetch example is a separate conspicuous route.
It has an explicit HTTPS fetch policy and a different CSP, and is never used
by the local playground. No page contains analytics, telemetry, upload code,
CDN dependencies, or object URLs.

`npm run docs:serve` serves the static site, built package, and test assets
from this repository on a loopback address. The checked browser server uses
the same CSP and local-only policy during CI. The production evidence is a
static build, generated-link check, real static serving, browser navigation,
search, playground, accessibility, CSP, and local-network test—not a
screenshot or an assertion that a development server merely started.

## Runtime recipes

`docs-site/recipes.html` contains boundary examples for browser, worker, Node,
Deno, Bun, Vite, Next.js, React, and serverless runtimes. Browser, worker,
Node, package, and browser-site paths are exercised in this repository. Deno
and Bun are listed as conditional and remain explicitly unverified when the
runtime is not installed; neither is presented as tested support.

## Evidence

Focused evidence is retained in `tests/docs-site.test.ts` and
`tests/browser/docs-site.spec.ts`. The generated inventory is retained in
`docs-site/generated/site-data.json`, `site-data.js`, and `MANIFEST.md`.
`npm run docs:check` is part of `npm run check`; the browser suite exercises
Chromium and Firefox. WebKit remains separately reported as unavailable in
`RUNTIME_SUPPORT.md` when its installed Playwright runtime cannot launch.
